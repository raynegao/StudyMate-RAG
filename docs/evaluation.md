# StudyMate RAG quantitative evaluation

This report is generated by `scripts/evaluate_rag.py` from a fully fictional, public Chinese benchmark. It contains 30 questions over 3 PDFs. Every question has a gold document, page and answer-keyword set. Dataset SHA-256: `42c846e47f4cbbb82bac54f3861da4391b74121fbe93594d213bc9b05fa648a4`.

## Retrieval methodology

- Embedding model: `BAAI/bge-small-zh-v1.5` with normalized vectors
- Relevance rule: document and a manually accepted page must match; original-page-only recall is also retained in JSON
- Metrics: Recall@K, MRR@K, mean retrieval latency and P95 retrieval latency; BGE latency includes query embedding after a warm-up inference
- Comparison: BGE versus character 2/3-gram Jaccard, across three character limits and five `top_k` values; all splits also respect sentence boundaries and the 384-token budget including special tokens
- Environment: Python 3.12.13, sentence-transformers 3.3.1, torch 2.5.1
- Measured at: `2026-10-18T00:03:02.140903+00:00` on `macOS-26.5.1-arm64-arm-64bit`

## Reproduce

```bash
.venv/bin/python scripts/generate_evaluation_assets.py
.venv/bin/python scripts/evaluate_rag.py

# Also call the configured answer model for answer and citation metrics
set -a && source .env.local && set +a
.venv/bin/python scripts/evaluate_rag.py --with-llm
```

The machine-readable result, including per-question grounded-answer evidence, is stored in [evaluation result JSON](../output/evaluation/evaluation-results.json).

## Limitations

- The benchmark is deliberately small and synthetic, so it measures reproducibility rather than production-domain generalization.
- Keyword correctness is deterministic and auditable, but it does not replace expert grading of nuanced free-form answers.
- Model output and latency can change across provider versions and network conditions; retrieval results are locally reproducible without an API key.

See [real-course evaluation](real-course-evaluation.md), [answerability evaluation](answerability-evaluation.md) and [hard-question evaluation](hard-evaluation.md) for real-domain retrieval, unsupported-question tests and harder question types. This benchmark saturates, so use the hard-question set to judge retrieval changes.
